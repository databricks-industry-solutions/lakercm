# Contributing to LakeRCM

LakeRCM is a Databricks solution accelerator. It accepts contributions from
Databricks employees only. If you are not one and have found a problem or have
an idea, please open an issue; for anything sensitive, follow
[SECURITY.md](SECURITY.md) instead.

2. **You grant us a license to use your contribution.**

3. **You are not submitting confidential or proprietary information.**

If you are contributing on behalf of an organization, you confirm that you have the authority to do so. You agree to confirm these terms in your pull request. Any request that does not explicitly accept the terms will be assumed to have accepted.

## Pull requests

- **Open the pull request against `dev`** from a topic branch. `dev` deploys to
  the development workspace on merge; `main` is promoted from `dev` and deploys
  to production only after a reviewer approves the deployment. Either deploy
  runs only once CI and the security scans pass on the merged commit.
- **Peer review is required.** Every pull request needs an approving review from
  someone other than the author, and the first review of a change to published
  content includes an L7+ reviewer. CODEOWNERS assigns reviewers by path.
- **One concern per pull request**, described in its body: what changed, why,
  and how you verified it.
- **Keep CI green.** Lint, tests, the frontend build, pre-commit and
  `bundle validate` run on every pull request, and again before every deploy
  ([`.github/workflows/ci.yml`](.github/workflows/ci.yml)). A pull request
  merges only once CI and the dependency audit pass.
- **Test against a workspace** when a change affects what deploys: merge to
  `dev`, or run `./scripts/deploy.sh --target dev` against your own workspace
  ([docs/local-dev-setup.md](docs/local-dev-setup.md)).

Changes to authentication, grants, Lakebase migrations, the agent's system
prompt, or a new third-party dependency need a security or subject-matter
reviewer as well as the path owner.

## What belongs in the repository

- **No workspace-specific values.** Catalog names, service principal ids,
  hostnames and workspace URLs are required bundle variables with no default
  (`bundles/_shared/variables.yml`), supplied per target by an env file
  ([`.env.example`](.env.example)) or a GitHub Environment.
- **No credentials.** No tokens, passwords, keys or service-account files.
  `pre-commit` runs `detect-private-key`, and GitHub secret scanning blocks
  pushes that contain known secret formats.
- **No real or customer data.** Only synthetic data, generated by code. No
  documents, identifiers or names from a real patient, provider, payer or
  customer.
- **Only compatible licenses.** Third-party code, packages and assets must be
  Apache-2.0, BSD, MIT or Databricks licensed, and each is listed in
  [NOTICE.md](NOTICE.md). Anything else needs legal approval first.

## Code style

The repository uses [pre-commit](https://pre-commit.com/) with `black`, `ruff`,
`detect-private-key`, `check-yaml`, `check-json`, `check-added-large-files` and
`check-merge-conflict`. Install the hooks once:

```bash
pre-commit install
```
